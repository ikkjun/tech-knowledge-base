# 인증 없이 루트 권한 탈취... 리눅스 'NFS2ROOT' 제로클릭 경보

> **출처:** [원문 보기](https://www.boannews.com/news/articleView.html?idxno=147562) (조재호 기자, 2026.11.26)

## 📌 Keywords
- NFS2ROOT (CVE-2026-99362)
- 리눅스 커널 내장 `nfsd`
- 제로클릭 (Zero-click) RCE
- 커널 힙 버퍼 오버플로

## 🚨 주요 내용 요약

### 1. 문제 상황: 12년간 잠복한 리눅스 커널 내장 `nfsd` 제로클릭 취약점 공개
보안 연구 조직 오픈섹 인텔리전스(OpenSec Intelligence)가 리눅스 커널 내장 네트워크 파일 시스템 서버(`nfsd`)에서 계정 인증이나 사용자 클릭 없이 최고 관리자(`root`) 권한을 탈취할 수 있는 원격 코드 실행(RCE) 취약점 'NFS2ROOT'(CVE-2026-99362, CVSS 9.8점)를 공개했다. 2014년 3월 리눅스 커널 3.16에 유입된 이 결함은 12년간 장기 지원(LTS) 및 주요 배포판 커널 전반에 남아 있었으며, TCP 2049 포트로 조작된 패킷을 전송하는 것만으로 발동된다.

### 2. 발생 원리 및 위험성: 커널 힙 버퍼 오버플로와 주요 배포판 패치 공백
클라이언트가 NFSv4.1·4.2 응답 캐시 크기를 최소치로 협상해 슬롯 버퍼를 0바이트로 만든 뒤 조작된 복합(COMPOUND) 요청을 보내면, 0바이트 힙 버퍼에 80바이트 응답이 복사되며 경계 밖 61바이트를 덮어쓰는 오버플로가 발생한다. 공격자는 이를 악용해 커널 메모리 보호(KASLR)를 우회하고 원격 루트 셸을 실행할 수 있다. 업스트림 커널은 수정되었으나 11월 26일 기준 레드햇(RHEL 7~10, 오픈시프트 4~5)과 우분투(26.04 LTS 등)는 공식 보안 패치를 배포하지 않은 상태이며, 내부망 침투 후 공유 스토리지나 쿠버네티스 노드를 장악하는 경로로 악용될 위험이 크다.

### 3. 패치 현황 및 향후 전망: 배포판 패치 공백과 N-day 무기화 우려
업스트림 커널 패치는 공개되었으나, 레드햇(RHEL 7~10)과 우분투(26.04 LTS 등) 주요 엔터프라이즈 배포판은 아직 공식 보안 패치를 배포하지 않은 상태다. 공격 코드는 비공개로 유지되었지만 상세 공격 원리가 공개됨에 따라, 패치 공백을 노린 N-day 공격 무기화가 빠르게 진행될 것으로 전망된다.

## 💡 핵심 질문 (Q&A)
**Q. 지난번 'NGINX2Root'는 웹 서버 침투 후 별도의 커널 권한 상승 취약점을 결합해야 `root` 권한을 얻었는데, 왜 'NFS2ROOT'는 단 한 번의 공격으로 즉시 `root` 권한이 탈취되는가?**<br>
**A.** 실행 권한 계층(User Space vs Kernel Space)의 차이 때문이다. 엔진엑스(NGINX)는 운영체제 위의 '사용자 공간'에서 `nginx` 같은 낮은 권한의 워커 프로세스로 격리되어 실행되므로 뚫리더라도 일반 계정 권한만 얻는다. 반면 리눅스의 `nfsd`는 파일 입출력 성능을 극대화하기 위해 운영체제 핵심인 **커널 공간(Kernel Space) 내부에 내장되어 최고 권한(`uid=0`)으로 직접 동작**하기 때문에, 메모리 오염과 코드 실행에 성공하는 순간 별도의 권한 상승 단계 없이 곧바로 시스템 전체의 `root` 권한을 장악하게 된다.

## 🛡️ 대응 방안 및 탐지 지침
- **4대 항목 점검 및 커널 업데이트:** 운영 서버 커널 버전(3.16 이상), `nfsd` 모듈 적재 여부, NFSv4.1·4.2 활성 상태, TCP 2049 포트 개방 여부를 점검하고 해당 시 수정 커널로 업데이트 및 재부팅한다.
- **방화벽 격리 및 임시 완화:** 배포판 패치 전이라면 인가된 스토리지 대역 외 TCP 2049 접근을 차단하고, 즉시 적용이 어려울 경우 `/etc/nfs.conf`에서 NFSv4.1·4.2를 비활성화한 뒤 서비스를 재시작한다.
- **커널 로그 및 이상 징후 감시:** 정상 NFS 트래픽과 유사해 네트워크 탐지가 어려우므로 커널 로그의 `nfsd4_check_resp_size` 경고와 커널 워커의 비정상 셸 실행 흔적을 집중 모니터링한다.

## 📖 용어 사전
- **nfsd (NFS Daemon)** 
    - 용도: 파일 시스템 조작에 대한 클라이언트 요청을 서비스한다.
    - 설명: nfsd 디먼은 서버에서 실행되며 파일 시스템 조작에 대한 클라이언트 요청을 처리한다.
- **제로클릭 (Zero-click)** 
    - **제로클릭(Zero-Click)**은 사용자가 검색 결과 페이지나 AI 요약에서 원하는 정보를 얻고 외부 웹사이트 링크를 클릭하지 않는 현상을 말한다. 
    - **제로 클릭 공격**은 소프트웨어의 취약성을 이용하여 사용자 상호 작용 없이 공격을 수행한다. 이 취약점을 악용하여 익스플로잇은 멀웨어 또는 대상이 링크를 클릭하거나, 악성 파일을 열거나, 다른 조치를 취할 필요 없이 사용자의 디바이스에서 다른 악의적인 상호 작용을 수행할 수 있다.
- **KASLR (Kernel Address Space Layout Randomization)** 
    - Kernel Adress Space Layout Randomization (KASLR)은 Linux 커널의 보안을 개선하기 위해 함께 작동하는 두 부분으로 구성되어 있다.
        - **커널 텍스트 KASLR**: 커널 텍스트 자체의 물리적 주소 및 가상 주소는 다른 위치로 임의로 지정된다. 커널의 물리적 주소는 64TB 미만의 아무 곳에나 있을 수 있지만 커널의 가상 주소는 [0xffffffffffffffffffffffffffffffffffffffffffffffffffffffffffc0000000] 간에 제한되며 1GB 공간이다.
        - **메모리 관리 KASLR**: 메모리 관리 KASLR에는 시작 주소가 특정 영역에서 임의의 3개의 섹션이 있다. 따라서 KASLR은 커널 주소 공간에 관심 기호가 어디에 있는지 확인하는 데 의존하는 경우 커널 실행을 악의적인 코드로 리디렉션하는 것을 방지할 수 있다.
- **조작된 복합 요청(Manipulated Compound Request):** 주로 네트워크 프로토콜(특히 SMB2/SMB3)이나 보안 취약점, 또는 API 및 시스템 통신 과정에서 여러 개의 개별 명령이나 요청을 하나의 패킷(메시지)으로 묶어 전송할 때, 그 구조나 데이터를 악의적으로 변조한 요청을 의미한다.
- **N-day**: 이미 공개되고 패치가 나온 취약점이다. "공개된 지 n일 지난" 취약점이라는 뜻이다. 패치가 있으니 이론상 막을 수 있는데도 여전히 위험한 이유는, 수많은 시스템이 그 패치를 안 깐 채 방치되기 때문이다.
